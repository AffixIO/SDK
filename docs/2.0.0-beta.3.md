# AffixIO SDK 2.0.0-beta.3: Security Notes

This build fixes three holes Articus found in beta.2 (`/workspace/zenoh-affixio/beta2-test/holes.mjs`). It builds on [2.0.0-beta.2](2.0.0-beta.2.md) (signer pinning).

## 1. Signed signing-time (HIGH)

**Problem:** key validity windows (`not_before` / `not_after` / `status: "retired"`) were checked against `signed_at`, but `signed_at` was not covered by the signature. Editing or deleting it let an expired key's envelope pass.

**Fix:** a new attestation schema, `affix.local-signature.v2` (the default). The ML-DSA signature and the HMAC cover:

```
canonical({ domain: "affix.sdk.local-signature.v2", key_id, payload, signed_at })
```

> Superseded in beta.4: the v2 bytes are now prefixed with `"affix.sdk.local-signature.v2\n"` (see 2.0.0-beta.4.md).

`canonical` is sorted-key JSON with no whitespace (`canonicalLocalPayload`). `payload_digest` is still `sha256(canonical(payload))`. Use `localSignatureMessage(payload, attestation)` to get the exact signed bytes, for example when porting a verifier to Rust.

Verification:
- v2 with a missing or unparseable `signed_at` fails (`invalid_signed_at`). An edited `signed_at` fails (`invalid_signature`).
- If the pinned key has a window or is retired, a signed time outside it fails (`key_outside_validity_window`). A revoked key fails (`key_revoked`).
- **Legacy v1 envelopes** (beta.1, beta.2 and 1.x, with an unsigned `signed_at`) still verify against a pinned key **with no window**. When a window applies they fail with `unsigned_timestamp`, unless `allowLegacyUnsignedTime: true` is set (insecure, for migration only).
- `signLocalPayload(..., { legacyV1: true })` still emits v1 for old verifiers.

**AffixIO API attestations.** The server signs only `SHA-256(JSON.stringify(payload))` (`/api/attest`, `/v1` proof responses). Its `signed_at` is **not** signed, and there is no `/v1/attest` route. We chose **not to change the server**. Instead, `verifyAffixioAttestation` treats API attestations as having **no signed time**:
- `signed_at` is never used for key validity.
- Revoked keys are rejected. Retired keys, and keys with `not_after`, are rejected (`unsigned_timestamp`), because they cannot prove they signed inside the window. `allowLegacyUnsignedTime: true` overrides this.
- `not_before` is checked against the verifier's clock.
- `requireSignedTime: true` rejects every API attestation.

If you need a time guarantee, wrap the API result in your own v2 envelope when you receive it. A future server release can add a signed time in a backward-compatible way, as a separate signature field.

## 2. Own-key trust on verifier roles

- `trustOwnSigningKey` is always honoured. Before, it was ignored unless `trustedSigningKeys` was also passed.
- `role: "device" | "edge" | "offline-verifier"` defaults to `trustOwnSigningKey: false` and `generateSigningKey: false`. A device no longer creates `.affix/secrets/mldsa65.json`, and doesn't trust one if it already exists, so a readable key file cannot mint commands the device accepts. Pin the gateway with `trustedSigningKeys`. To opt in, set `generateSigningKey: true, trustOwnSigningKey: true`.
- A verifier role with no signing key throws `no_local_signing_key` from `exportLocalPublicKey()` and from local `prove()`.
- With no pinned keys, `verifyLocal(..., { envelope })` throws `AffixTrustError("no_trusted_keys")`.

## 3. `valid` requires `envelope_ok`

When an envelope is supplied, `verifyLocal` returns `valid` / `verified` = proof valid **and** envelope valid. `decision` is `"no"` unless both pass. The proof-only result is in `proof_valid`.

## Device pattern (recommended)

```js
import { verifyLocalAttestation, createReplayGuard } from "affixio";
const gateway = JSON.parse(fs.readFileSync("gateway.pub.json")); // pinned at provisioning
const guard = createReplayGuard({ windowMs: 60_000 });

function accept(cmd, envelope) {
  const r = verifyLocalAttestation(envelope.payload, envelope.attestation, { trustedKeys: gateway }); // no HMAC secret on device
  if (!r.valid) return reject(r.reason);
  if (envelope.payload.decision !== "yes") return reject("decision_no");
  // Command binding: the signed payload must commit to THIS command (e.g. digest of canonical cmd).
  if (envelope.payload.payload_digest !== digestOf(cmd)) return reject("not_bound");
  return guard.check({ id: cmd.cmd_id, issuedAtMs: cmd.issued_at_ms }); // replay
}
```

A valid signature only proves who signed. Always check the decision and the command binding as well.

## key_id formats and aliases

- Local SDK key ids are `sha256(raw public key bytes)[0:16]` (hex).
- The AffixIO API key id is `mldsa65-` + `sha256(hex string of the key)[0:16]`. For the live key that is `mldsa65-1bf342d458b982b2`, and it is unchanged.
- `normalizeTrustedKeys` indexes every key under **both** its derived local id and any `key_id` given in the key set, so either form matches. `publicKeyHash(b64)` gives the full SHA-256 of the raw bytes, which is a format-independent identifier.

## Key-set trust: TLS trust-on-first-use and pinning

`fetchAffixioKeys()` trusts whatever `https://api.affix-io.com/v1/keys` returns over TLS on first fetch, then caches it for an hour. That is trust-on-first-use anchored in the web PKI. For stronger guarantees:
- **Offline pin:** ship the key set file with the device and pass it as `trustedKeys`. No fetch happens.
- **Pin by hash:** `fetchAffixioKeys({ expectedKeySetHash })`, using a hash from `computeKeySetHash(keySet)` (SHA-256 of the canonical, sorted key list), or `expectedKeyIds: ["mldsa65-1bf342d458b982b2" | publicKeyHash]`. A mismatch throws `affixio_keyset_pin_mismatch`.

## Replay store scope

`MemoryReplayStore` is **per process** and is lost on restart. Several verifier processes, or restarts inside the window, need a shared store implementing `putIfAbsent(id, expiresAtMs, nowMs) -> boolean` atomically (for example Redis `SET key 1 NX PXAT expiresAtMs`, or a database unique insert).

## Breaking changes (from beta.2)

- New envelopes are v2. Verifiers older than beta.3, including custom ports that verify `canonical(payload)`, cannot verify them. Use `legacyV1: true` while migrating.
- v1 envelopes fail against keys that have validity windows unless `allowLegacyUnsignedTime` is set.
- API attestations signed by a retired key, or a key with `not_after`, are rejected by default.
- Verifier roles no longer auto-create or trust a local key.
- `verifyLocal().valid` is false when a supplied envelope fails.
