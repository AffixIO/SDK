# AffixIO SDK 2.0.0-beta.4: Security Notes

This build fixes the holes Articus found in beta.3 (`/workspace/zenoh-affixio/beta3-test/attacks3.mjs`). It builds on [beta.3](2.0.0-beta.3.md) and [beta.2](2.0.0-beta.2.md).

## 1. Envelope ↔ proof binding (HIGH, V5)

`verifyLocal(proofA, { envelope: envelopeOfProofB })` used to report `envelope_ok: true`. Now `envelope_ok` is true only when the signature is valid **and** the envelope commits to the supplied proof:

- `payload.proof === proofHex`. If the payload has no `proof` field, `payload.proof_digest` must equal `sha256("<circuit>:<valid>:<proof>")`, computed from the supplied proof. A payload carrying a *different* `proof` never binds.
- **And** `payload.circuit_id === circuitId`. If the payload has no `circuit_id`, `payload.proof_mode` must equal the detected mode. A payload with neither does not bind.

Failure reasons: `envelope_proof_mismatch`, `envelope_circuit_mismatch`, `envelope_proof_mode_mismatch`. `valid` stays false whenever `envelope_ok` is false (beta.3).

The same rule is used by:
- `checkEnvelopeBinding(payload, { proof, circuitId, proofMode })`, exported from `affixio`.
- `affixio/browser` / `affixio/workflows` `verifyPublicEnvelope(env, { ..., proof, circuitId, proofMode })`. Binding is checked when `proof` is given.
- `affixio/offline` `verifyArtifactOffline({ proof: payload, attestation, trustedKeys, proofHex, circuitId })`, which adds a `proof_binding` check.
- Evidence bundles: each artifact is bound by its SHA-256 in the signed manifest (unchanged). To check a proof inside a bundle against an envelope, use one of the functions above.

## 2. v1/v2 domain separation (MEDIUM, X1)

The v2 signed bytes are now `"affix.sdk.local-signature.v2\n" + canonical({ domain, key_id, payload, signed_at })`. Canonical JSON always starts with `{ [ " digit - t f n`, so no v1 message (`canonical(payload)`) can equal a v2 message, and a v1 signature can never verify as v2. `localSignatureMessage()` and `LOCAL_SIGNATURE_V2_PREFIX` reflect this.

- `signLocalPayload(..., { legacyV1: true })` refuses payloads with a top-level `domain`, or shaped like a v2 message (`payload` + `signed_at` + `key_id`). The error is `legacy_v1_refused`.
- v1 verification rejects v2-shaped payloads (`legacy_v1_v2_shaped_payload`).
- **New option `rejectLegacyV1`** (on `verifyLocalAttestation`, `verifyPublicEnvelope`, `verifyArtifactOffline`, `verifyLocal` and the SDK config):
  - **Default `true` for `device` / `edge` / `offline-verifier`**: verifier roles are new deployments and verify v2 gateways, so rejecting v1 costs them nothing.
  - **Default `false` for `server` / `trusted-party`**, so existing stored v1 envelopes (1.x to beta.2) still verify on servers.
  - Reason when rejected: `legacy_v1_rejected`.

**Breaking:** v2 envelopes signed by beta.3 used the unprefixed message, so they do not verify on beta.4. beta.3 was never published; re-sign with beta.4.

## 3. Key-set pinning by bytes (MEDIUM, K4/K5)

`fetchAffixioKeys({ expectedKeys: [{ key_id, public_key_hash }] })` pins the key bytes. `public_key_hash` is SHA-256 hex of the raw key, from `publicKeyHash(b64)`.

- Every key in the fetched set must be pinned, with the correct hash for its id. **Unexpected extra keys are rejected** (`affixio_keyset_pin_mismatch`), not ignored. A tampered set is a signal worth failing on, and silently trimming it would hide the compromise. To rotate, add the new key's pin before the server publishes it.
- At least one pinned key must be present.
- `expectedKeySetHash` (exact-set pin) still works.
- **`expectedKeyIds` is not a security control.** It only checks presence, so extra or swapped keys pass. Used on its own it emits the `AFFIXIO_KEY_IDS_NOT_A_PIN` warning.

Pin for the live key: `{ key_id: "mldsa65-1bf342d458b982b2", public_key_hash: publicKeyHash(<public_key_b64 from /v1/keys>) }`.

## Low

- `allowLegacyUnsignedTime` now emits the `AFFIXIO_ALLOW_LEGACY_UNSIGNED_TIME` warning (`console.warn` in the browser), for local and API attestations alike.
- Tests cover the accept and reject paths for API attestations signed by active, retired, expiring, expired and revoked keys, with and without `allowLegacyUnsignedTime`.
