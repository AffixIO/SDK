**AffixIO** (`affixio` on npm) is the Node.js SDK for **privacy-preserving** proofs with **post-quantum** attestation. Prove eligibility, KYC outcomes, age checks, residency, and other predicates **without exposing raw credentials**. Proofs are generated on your host, signed with **ML-DSA-65 (FIPS 204 / Dilithium)**, and verifiable locally or through the AffixIO API — including **Merkle audit**, **signed tree head (STH)**, and **consistency proofs**.

Also in the package: **Know Your Agent (KYA)** for **agentic AI**, the **Agentic Pay** kit (`agenticPay`, `x402BeforePay`, `mcpToolGate`, payment mandates / **AP2**), plus **offline-first** and **air-gapped** operator modes. Not person KYC — agent capability and spend attestation.

Built for developers using [Noir](https://noir-lang.org/) circuits, [Barretenberg](https://github.com/AztecProtocol/barretenberg) (**UltraHonk**), **verifiable credentials**, **crypto-agility**, and [NIST PQC](https://csrc.nist.gov/projects/post-quantum-cryptography).

### Policy / version binding (1.4.1)

Every local proof envelope payload now includes:

- `policy_hash` — SHA-256 of the canonical policy JSON that produced the decision (or a documented empty-policy sentinel)
- `version_binding` — `{ sdk_version, circuit_id, attestation_schema: "affix.local-signature.v1", envelope_schema: "affix.proof-envelope.v1", policy_revision }`

Pass `policy` / `policyRules` / `policyHash` to `prove()`. Agentic pay binds the active policy rules automatically. Helpers: `canonicalPolicyHash`, `buildVersionBinding` (also via `affixio/extensions`). Tampering `policy_hash` fails `verifyProofEnvelope`.

## Why AffixIO

Classical signatures (ECDSA, EdDSA, RSA) are vulnerable to future quantum attacks via Shor's algorithm. NIST finalised ML-KEM, ML-DSA, and SLH-DSA in 2024. AffixIO combines:

- **Local proof generation** over bundled Noir circuits (`simple_yesno`, `yesno`), with **UltraHonk** zero-knowledge proving as a proof mode
- **ML-DSA-65 (FIPS 204)** signatures on every proof, plus an HMAC envelope checked before `prove()` returns — **crypto-agility** without rewriting your app layer
- **Remote verification and Merkle anchoring** (inclusion proofs, STH, consistency) when online
- **Offline-first / air-gapped** paths for unreliable networks and regulated environments

Your witnesses and credentials never leave the host unless you explicitly verify or flush through the API.

## Architecture

```
Your service                         affixio (in-process)              AffixIO API
┌──────────────────────┐             ┌─────────────────────────┐      ┌────────────────────────────┐
│ Express / Fastify    │  import     │ prove() / verifyLocal() │HTTPS │ GET  /v1/auth/check        │
│ Next.js API route    │ ──────────► │ ML-DSA-65 envelope      │─────►│ GET  /v1/quota/consume     │
│ BullMQ / cron worker │             │ QR / barcode carriers   │      │ POST /v1/circuits/:id/verify│
│ LangChain / MCP tool │             │ data-check → prove      │      │ POST /v1/merkle/audit      │
│ Agentic pay / x402   │             │ STH · consistency       │      │ GET  /v1/merkle/root       │
└──────────┬───────────┘             │ offline verify kit      │      │ /.well-known/affix-mldsa65 │
           │                         └───────────┬─────────────┘      └────────────────────────────┘
           │                                     ▼
           │                          .affix/proofs.json
           │                          .affix/offline-queue.json
           │                          .affix/spend/  (tamper-evident journal)
```

**Typical integration points**

- **API middleware** — prove a predicate before payout, account change, or data export
- **Background workers** — batch eligibility; `flushOfflineQueue()` when connectivity returns
- **LLM / agentic AI** — gate tools and model tiers with a proof; never put raw KYC into the prompt
- **MCP tools** — return `proof_id` with tool results so downstream systems verify without credentials
- **Audit pipelines** — attach a proof digest via Merkle anchoring + STH

Install the package in the service that holds secrets. Do **not** embed API keys in browser bundles or client-side LLM prompts.

## Quick start

Save your key once (mode `0600` at `.affix/secrets/api.key`), or export `AFFIX_API_KEY`:

```bash
npx affix-sdk set-key --api-key aio_live_...
```

```typescript
import { AffixSDK, defaultContext } from "affixio";

const sdk = new AffixSDK({ apiKey: process.env.AFFIX_API_KEY });

const credential = {
  schema_id: "eligibility_v1",
  issuer_id: "issuer_abc",
  issuer_pubkey_hash: "0x1",
  credential_id: "0x2",
  claim_value: "approved",
  valid_from: 1700000000,
  valid_until: 1800000000,
};

const required = "approved";
const decision = credential.claim_value === required ? "yes" : "no";

const result = await sdk.prove({
  circuitId: "simple_yesno", // bundled: simple_yesno | yesno
  decision,
  credential,
  context: defaultContext({ required_claim_hash: required }),
});

console.log(result.proof_id, result.valid, result.decision);

const check = await sdk.verifyLocal("simple_yesno", result.proof, {
  proofId: result.proof_id,
  envelope: result.envelope,
});
console.log(check.valid, check.proof_mode, check.envelope_ok);
```

`new AffixSDK()` needs an API key: pass `apiKey`, export `AFFIX_API_KEY`, or store it with `affix-sdk set-key`.

```bash
npx affix-sdk health                      # API health + circuit catalogue (115 circuits)
npx affix-sdk prove --claim approved      # local proof (--offline skips licence RTT)
npx affix-sdk list
npx affix-sdk verify-local <proof-hex>
```

## Agent trust & agentic payments

**Know Your Agent (KYA)** enrols an agent with a capability spec; every tool call can carry host-side signed ACTION attestation. **Agentic payments** layer spending limits, **x402**-style paid endpoints, **AP2**-style mandates, and **MCP tool** gates — so agentic AI can pay without leaking credentials into the model.

```typescript
import { createAgentTrust } from "affixio/agent-trust";
// Agentic Pay Kit also available from the main package surface:
// agenticPay, x402BeforePay, mcpToolGate, createPaymentMandate, ...
```

```bash
node examples/agentic-pay/agentic-pay.mjs
node examples/mcp-tool-gate/tool-call.mjs
PORT=8799 node examples/x402-before-pay/server.mjs
curl -s -H 'x-agent-id: agent://research-runner' http://127.0.0.1:8799/paid-report
```

Each call returns an `allowed` decision and a signed receipt with `proof_id` / `proof_digest`; the x402 server answers `402` when policy denies.

### 3. Prove before the LLM (tool router)

Verified pattern: the model sees the outcome, never the credential.

```typescript
import { AffixSDK, defaultContext } from "affixio";

const sdk = new AffixSDK({ apiKey: process.env.AFFIX_API_KEY });

export async function beforeToolRun(claimValue: string, required: string) {
  const allowed = claimValue === required;
  const { valid, proof_id } = await sdk.prove({
    circuitId: "simple_yesno",
    decision: allowed ? "yes" : "no",
    credential: {
      schema_id: "eligibility_v1",
      issuer_id: "issuer_abc",
      issuer_pubkey_hash: "0x1",
      credential_id: "0x5",
      claim_value: claimValue,
      valid_from: 1700000000,
      valid_until: 1800000000,
    },
    context: defaultContext({ required_claim_hash: required }),
  });
  if (!allowed || !valid) throw new Error("tool_access_denied");
  return proof_id; // logs / Merkle audit — not the model context
}
```

For a decision made **inside** the ZK proof, pass `proofMode: "ultrahonk"` and omit `decision`.

## Proof modes

| Mode | Use it for | Speed |
|------|------------|-------|
| `hmac` (default) | High-throughput yes/no with authenticated, ML-DSA-65 signed result | sub-millisecond |
| `ultrahonk` | Real **zero-knowledge** proofs over bundled Noir circuits | ~1s |

```typescript
const zk = await sdk.prove({
  circuitId: "simple_yesno",
  proofMode: "ultrahonk",
  credential,
  context: defaultContext({ required_claim_hash: "approved" }),
});
```

| Mode | Who decides |
|---|---|
| `hmac` | Your caller via `decision: "yes" \| "no"` (bound into HMAC + ML-DSA-65 envelope) |
| `ultrahonk` | The Noir circuit (claim/required comparison inside the proof) |

UltraHonk proofs are what the AffixIO API can re-verify and Merkle-anchor. HMAC proofs verify locally with `verifyLocal()`. Verification fails closed.

Remote `verify()` / `flushOfflineQueue()` are disabled while `licenceOnly` is true (default). Opt in:

```typescript
const sdk = new AffixSDK({ apiKey, licenceOnly: false, autoFlush: true });
```

```bash
AFFIX_LICENCE_ONLY=0 npx affix-sdk flush
```

Or in `.affix/config.json`: `{ "version": 1, "licenceOnly": false, "autoFlush": true }`.

## Post-quantum attestation

Every proof is signed with **ML-DSA-65** (**FIPS 204**, CRYSTALS-**Dilithium** family) by a key owned by your deployment, wrapped in an HMAC envelope re-checked before `prove()` returns. API responses can carry ML-DSA-65 attestations. Aligns with [NIST IR 8547](https://csrc.nist.gov/pubs/ir/8547/final) toward quantum-resistant cryptography and long-term **crypto-agility**.

```typescript
proof.signature;             // { algorithm: "ML-DSA-65", key_id, signature_b64, ... }
sdk.exportLocalPublicKey();  // publish so verifiers can check your signatures
```

Platform attestation key (well-known, not a secret):

https://api.affix-io.com/.well-known/affix-mldsa65.json

Proving backend: Noir → ACIR, Barretenberg **UltraHonk** for `ultrahonk` mode ([Noir web app guide](https://noir-lang.org/docs/dev/guides/building_a_web_app)).

## Offline queue & air-gapped ops

Proofs are produced locally — an API outage does not stop proving. What changes is when verification, attestation, and anchoring happen.

1. Offline proof → stored with `offline: true`, `pending_sync: true`
2. With `licenceOnly: false` and `queueUnsyncedProofs: true` (or `queueProofForAffix()`), enqueued in `.affix/offline-queue.json`
3. `flushOfflineQueue()` verifies, collects ML-DSA-65 attestation, anchors digests. `autoFlush: true` ≈ every 5s while non-empty

Local paths: `.affix/proofs.json`, `.affix/offline-queue.json`, `.affix/spend/`, `.affix/secrets/` (mode `0600`).

For fully **air-gapped** verify of inclusion + STH + attestation, use `verifyArtifactOffline` from `affixio/offline` (no API key required for that path).

## Use cases

### AI, LLMs, and agentic AI

Large language models should not receive passports, medical records, or full KYC payloads just to answer "is this user allowed?". A trusted backend proves a yes/no predicate and hands the model only the outcome — **privacy-preserving** by design.

| Scenario | Circuit examples | What you prove without exposing |
|---|---|---|
| Tool gating | `attested_boolean`, `kyc` | Tier / standing / clearance |
| RAG access | `attested_membership`, `edu_enrollment_verification` | Role without employee IDs |
| Age / consent | `health_age`, `ent_age_restriction` | Threshold met, not DoB |
| Healthcare assistants | `health_consent_verification` | Consent / eligibility, not PHI |
| Cross-border policy | `travel_visa_eligibility` | Eligibility flag, not passport |
| Agent audit trail | `audit_proof`, `merkle_batch` | Decision proved at a point in time |

Locally provable today: `simple_yesno` and `yesno`. Hand `proof_id` to logs or Merkle audit — never to the model context.

### Agent spend (KYA and Agentic Pay)

- **Know Your Agent** — `createAgentTrust()`
- **Agentic Pay** — `agenticPay()`, `verifyAgentSpend()`, `createPaymentMandate()`
- **x402 / paid APIs** — `x402BeforePay()`, `paidApiAgentPolicy()`
- **MCP tools that create cost** — `mcpToolGate()`
- **Receipts** — `createAgentCheckoutReceipt()`
