# AffixIO SDK 2.0.0-beta.5: Security Notes

This build fixes the remaining findings from Articus's beta.4 run (`/workspace/zenoh-affixio/beta4-test/attacks4.mjs`).

## 1. Binding is explicit and required (MEDIUM)

beta.4 skipped proof binding silently when no proof was supplied. Now:

| Verifier | Default | Result fields |
| --- | --- | --- |
| `verifyArtifactOffline` (with an attestation) | Requires `proofHex` + `circuitId` (or `proofMode`). Otherwise a failing `proof_binding` check (`binding_required`) | `bound`, `binding: "checked" \| "skipped" \| "missing"`, `unbound` |
| `verifyPublicEnvelope` (`affixio/browser`, `affixio/workflows`) | Requires `proof` + `circuitId` (or `proofMode`). Otherwise `valid: false` with reason `binding_required` / `binding_needs_circuit` | `bound`, `binding`, `unbound` |
| `AffixSDK.verifyLocal` | Always binds when an envelope is supplied (beta.4) | `envelope_ok`, `envelope_reason` |

**Default chosen: fail closed.** `allowUnbound: true` verifies only the signature. The result is marked `binding: "skipped"`, `unbound: true`, `bound: false`, and a warning is emitted once (`AFFIXIO_UNBOUND_ENVELOPE` / `console.warn`). CLI: `affix-sdk-ext verify-offline ... --proof-hex file --circuit-id id`, or `--allow-unbound`.

To break as little as possible, evidence-bundle manifests are not proofs, so `verifyEvidenceBundle` checks the manifest signature without binding (unchanged), plus the artifact digests.

## 2. Legacy v1 default on every verifier (MEDIUM-LOW)

- Standalone `verifyLocalAttestation`, `verifyLocalPayload`, `verifyProofEnvelope`, `verifyPublicEnvelope`, `verifyEvidenceBundle` and `verifyArtifactOffline` now **reject v1 by default**. Opt in with `rejectLegacyV1: false`. The CLIs take `--accept-legacy-v1` (`affix-sdk-ext`) and `--accept-legacy-v1 yes` (`affixio-evidence`).
- New `sdk.verifyLocalAttestation(payload, attestation, options?)` applies the instance's role defaults: pinned keys, `rejectLegacyV1` (true for verifier roles, false for server roles), HMAC only on trusted roles, and the insecure flag. Options override them. **This is the documented device path.**
- I reviewed the other verifiers: `sdk.verifyLocal` already used the role default. The standalone verifiers have no role and now use the strict default. `verifyAffixioAttestation` is not affected, because API attestations have no v1/v2 schema.

## 3. Decision and digest binding (LOW)

- A `proof` or `proof_digest` field that is not a string never binds; for example `proof: [A]` cannot fall through to the digest path (attacks4 B13).

- When the proof result and the envelope payload both carry a decision, they must match (`envelope_decision_mismatch`). `verifyLocal` passes the proof's decision automatically. For the standalone verifiers, pass `decision`.
- When the payload carries both `proof` and `proof_digest`, both must match the supplied proof (`envelope_proof_digest_mismatch`).

## Device pattern (updated)

```js
const sdk = new AffixSDK({ apiKey, role: "device", trustedSigningKeys: [gatewayPub] });
const r = sdk.verifyLocalAttestation(envelope.payload, envelope.attestation); // role defaults: v1 rejected, ML-DSA only
if (!r.valid) reject(r.reason);
// then: decision === "yes", command binding (payload commits to this command), replay guard
```
